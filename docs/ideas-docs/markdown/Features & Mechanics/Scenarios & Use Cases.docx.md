Scenarios & Use Cases

**General Scenarios**

* Reviewers will regularly create empty topics, arguments about the necessary and very important areas of knowledge, truth. These will aid in guiding the contribution and as starting points of discussion. Contributing empty topics and arguments is also open to regular contributors.
* Users can flag/vote on topics that requires attention or top priority.

**User Capabilities**

Contributor

* Post new content, edit (pending)
* Tag for issues, metadata (pending)
* Upvoting content, tags

Peer Reviewer

* Accept/approve/confirm content, tags
* Tag for issues, metadata (pending)
* Re-arrange, organize content (without approval?). Probably should start a discussion first and gather votes (non-critical vote)?

**Discussion Threads & Comments**

* Argument/Discussion, Answer
* The official thread is strict and the logic should be unique as it serves the reasoning/justification of the argument
* Each reply in the thread can have a localized discussion on the actions/disputes by the user and editors.
* The localized discussion is less strict, but still follows minor rules for a fair and ethical discussion.
* A localized discussion is like a Wikipedia's dispute resolution
* Clean-up can be performed by deleting irrelevant points, merging replies?

Unrated Discussion / Comments

* Another tab of discussion intended for users (readers) to express their emotion but does not correspond to being true or accurate.
* There is less rules applied here.
* Truth value not counted - applies to Topics, Arguments, Sub-arguments
* Timeline - for every topic, argument, comment a single timeline is available to display events, unrated comments from any contributor (group comments).

Comment Types

* Single-threaded group on issue tags
* Multi-threaded 1-to-1 + single-threaded group on arguments

Tags, Arguments, Questions

* Categorized

**Content & Structure**

* Body: prefer structured content over large block of texts (wikipedia) to prevent versioning/editing issue/disputes. structured, list-type content works like small units which are easy to move, rearrange and discuss.
* Description or short content is important
* Arguments: As short and concise as possible to make understanding easier

**Topic & Argument Discussion**

* Comments should be classified as Supplement or Objection (aside from Question). Should we rename the first comment then as Supplement or Object and no longer a comment?
* A Supplement or Objection may contain multiple 1 vs 1 discussions. Or can we consider this as already an argument?
* A discussion has a maximum number of comments. More than that means it's no longer healthy.
* The discussion history includes comments, revisions, tagging just like an issue/PR discussion in github.
* When an argument is revised, previous comments may become irrelevant and should be edited/revised as well or tagged as irrelevant for hiding (comments have history too). One a comment became subject for revision due to argument revision and the owner did not edit it for 1 month, the comment will be subject for takeover by other users/peer reviewer.

**Obsoleting Arguments, Comments**

* Similar to github (fixes #2): Obsoletes comment #12, fixes/resolves tags #123. How will this work?
* If a comment becomes orphan due to revisions, some issues may arise and tags will be applied.
