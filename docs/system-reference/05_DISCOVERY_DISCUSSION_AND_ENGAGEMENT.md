# Discovery, Discussion, and Engagement

## Reading and Navigation Modes

Common patterns from source corpus:

- multiple reading densities (raw vs curated views)
- context sidebars (parents, siblings, children)
- outline and graph views for topology understanding
- optional timeline mode for temporal contexts

Normalized reading mode options:

- `Verified-first`
- `Include pending/unreviewed`
- `Show metadata/issues`
- `Timeline`
- `Graph`

## Discussion Architecture

Two clear discussion needs appear in source docs:

1. strict dialectic threads
- intended for evidence-driven claim progression
- can enforce cadence/quality constraints

2. general comments/opinions
- emotional/user voice channel
- lower strictness, no direct verdict power

## Home and Explore Patterns

Repeated expectations:

- `Latest`, `Trending`, and `Top` sections
- mixed-type discovery feed with filters
- role-specific queue widgets (screeners/reviewers)
- concise summaries in list rows for fast scanning

## Ranking Inputs (Suggested)

Based on backlog/research notes:

- recency/activity
- reviewer signals
- issue severity
- user reactions (popularity only, not truth)
- unresolved controversy weight

## Notifications and Follow

Desired event model from source notes:

- follow entries/topics
- notify on replies, status changes, verdict changes, mentions, and major edits
- notification center with unread counts and deep links

## Reaction Model

Suggested separation from sources:

- popularity reactions: upvote/downvote, expose/bury
- value reactions (ethical channel): good/bad and subtypes
- verdict actions: reviewer-controlled and evidence-aware

Key rule:

- reactions should influence ranking/visibility, not directly mutate truth status.

## Visualization Requirements

The corpus repeatedly asks for:

- network graph traversal with linked entity expansion
- configurable depth and item limits
- timeline view for entities/events
- quick switching between list and graph modes
